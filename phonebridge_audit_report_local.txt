FILE: Sources/PhoneBridgeCore/ScreenMirrorEngine.swift
--------------------------------------------------------------------------------
VERDICT: 1 medium defect + 1 negligible inconsistency.
- [M2] ScreenMirrorEngine.swift:249 - `.stopped` is effectively unreachable.
  Trace: the background task ends with
      if let self, await self.finishGeneration(runGeneration) { cont?.yield(.stopped) }
  `finishGeneration` (265-269) requires `generation == value`. Every path that
  ends the loop changes `generation` first: `stop()` (271-280) increments it;
  cancellation leaves the task cancelled but generation is only changed by
  stop(); deallocation makes `self` nil so the `if let` fails.
  Consequences: the `FrameEvent.stopped` case (179) and AppModel's handler at
  AppModel.swift:222-223 ("isMirroring = false") are dead code. Any future
  consumer that waits for `.stopped` to know the stream ended will hang.
  FIX: in `stop()`, after `previous?.cancel()` / `await previous.value`, yield
  `.stopped` directly from the actor (`continuation?.yield(.stopped)`), and drop
  the generation check at 249 (or keep it only for the self-terminated case).
- [negligible] ScreenMirrorEngine.swift:285 vs 259 - `captureOnce` uses
  `sequence += 1` (trapping) while `publish` uses `sequence &+= 1` (wrapping).
  Mixing them means 2^64 captureOnce calls would crash instead of wrap. Fix:
  use `&+=` in captureOnce for consistency.
- Concurrency audit: actor isolation is consistent; `[weak self]` capture in the
  task plus `await self.publish/isActive/finishGeneration` hops are legal and
  race-free; generation checks reject buffered old frames after stop/restart;
  `deinit` (289-292) cancels the task and finishes the continuation. The
  reentrancy interleaving of two concurrent start()/stop() calls was traced and
  is safe because stop() awaits `previous.value` before a later start sets a
  new generation. No @MainActor violation.

- [H1] KeepAlivePolicy.swift:346-360 (with 296-304) - `endMirrorSession` calls
  `takeMirrorSnapshot(serial:)` FIRST. `takeMirrorSnapshot` (296-304) sets
  `mirrorSnapshot = nil` when the serial matches - BEFORE any restore command
  runs. The three restores (349-359) are `runStep` calls that swallow adb errors
  into `ok: false` reports. If the device is unreachable, adb is missing, or any
  restore step fails, the reports say "failed" but the snapshot is already gone;
  a retry of endMirrorSession finds no snapshot (line 348 returns []) and never
  restores. The phone is left dimmed with stay_on_while_plugged_in=7 - exactly
  the state this feature exists to avoid. This also affects
  AppModel.shutdown/applyADBPath (both call endMirrorSession once).
  FIX: do not consume the snapshot until all three restores succeed. Add a
  `peekMirrorSnapshot(serial:)` that reads without clearing; run the restores;
  only if every step's `ok == true` call a `clearMirrorSnapshot(serial:)`. Keep
  the snapshot on partial failure so a later endMirrorSession/shutdown can retry.

  value at start(); the task sleeps with that constant (442). Changing
  `watchdog.interval` while running has no effect. (No UI currently exposes it.)
  FIX: read `await self.interval` each loop iteration inside the task.
- [L2b] KeepAliveWatchdog.stop() (449-454) is synchronous and does not await the
  in-flight task, unlike ScreenMirrorEngine.stop(). A rapid stop()/start() can
  overlap an in-flight `adb connect`/`policy.apply` from the old generation.
  The generation guard prevents state corruption but not concurrent subprocesses.
  FIX: make stop() async, capture the task, cancel it and `await task.value`.
- Verified correct: updateSettings validation (134-141); the read-back `runStep`
  semantics (172-207); `isShellWhitelisted` parsing (209-214); the mutually

VERDICT: 1 HIGH concurrency defect + 1 low.
- [H4] SequenceStore.swift:124, 130, 139, 158 - the class is `@unchecked
  Sendable` and declares `stateLock` (85), but in the `inMemory` code path the
  `memory: [UUID: MarkerSequence]` dictionary is read/written with NO lock:
